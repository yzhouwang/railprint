# CEO Plan: rail-geo durable package + N→N+1 migration + open ridelog

Generated by /plan-ceo-review on 2026-06-27

## Vision

### The durability thesis (10x)
Today RailPrint's geometry (`public/rail/*.json`) and the user's ridelog (IndexedDB) both die with the app, and a routine annual JP data refresh can silently erase a user's coverage. The 10x version: **both the geometry AND the user's data outlive the app**, IDs are stable-by-construction so refreshes never silently break coverage, China scales to a real network, and the geometry becomes a public good others fork and build on. A new engineer in 12 months sees a clean separation: an open, versioned `rail-geo` dataset (forkable, CDN-hosted), an open `ridelog` file spec (the user owns their data), and a thin app that consumes both.

### The reframe that gates everything (from adversarial critique)
The ask was "package extraction + migration UX." The critique found the **root-of-roots**: no ID in the system is deterministic. `segmentId = lineId:fromSeq-toSeq` is positional (a mid-line station insert shifts everything downstream), AND `lineId = jp-${operator}-${name}` gets a build-ORDER collision suffix `#${built}` (`n02-ingest.ts:621-630`) — so a pure N02 source *reorder* silently rewrites IDs with **no editorial "rename" to annotate**. You cannot build a reliable migration map (or claim "stable-by-construction" IDs) on top of non-deterministic IDs. **Fix ID determinism first; then migration shrinks to genuine semantic change.**

### Spike result (de-risks the foundation — run 2026-06-27 on the live 10,034-station dataset)
- 100% of stations carry a group code (`stationGroupId`); 0% of segments have a missing/shared/colliding endpoint group code.
- The content-addressed `segmentId = lineId:fromGroup-toGroup` scheme is a clean 1:1 remap from positional IDs **today** — no loop-arc/branch collisions.
- 0 of 594 lines currently carry the `#N` build-order suffix → the lineId landmine is *dormant* but real for the next vintage; defusing it is cheap insurance.

## Accepted Scope (the program, phased — each gate must pass before the next)

**Phase 0 — FOUNDATION (load-bearing; do first, ship behind no flag because it changes IDs):**
- Replace the build-order `#${built}` lineId disambiguator with a **deterministic content-hash** (`hash(operator + name + anchor-station-group-code)`); pin the operator slug in a **frozen overrides table** (operators rebrand; N02 normalizes names between vintages).
- Change `segmentId` from `lineId:fromSeq-toSeq` to `lineId:fromGroup-toGroup` (spike-validated). Loop lines: keep an explicit per-segment ordered pair (no ambiguity at segment level; arc direction is a route-marking concern, not a segment-id one).
- One-time, on-device remap of existing v0.9.x events (positional → group-pair) via the *previous* package as a static migration input — guarded (see Failure Modes).
- **The acceptance test (write FIRST):** build vN, build vN+1 with (a) a mid-line station inserted and (b) a slug-colliding line added earlier in source order; run the migration; assert a seeded user's coverage % and ridden-segment Set are byte-identical.
- Wire the **already-built-but-unconsumed** coverage-warning detection (`store` orphaned-segment / version-mismatch) into a `.svelte` banner — hours, zero schema change.

**Phase 1 — PACKAGE:** extract `public/rail/*` into a standalone versioned repo; GitHub Releases + CDN; a `manifest.json` (versions, namespaces JP/CN, per-file SHA-256, generatedAt, schema_version); **SHA-256 verification added to `fetchOne`** (today it checks country+crs only); a China-reachable **secondary fetch origin** (jsDelivr is unreliable in mainland China); per-namespace LICENSE (JP attribution-only, CN ODbL).

**Phase 2 — OFFLINE:** a Workbox **service worker** precaching the package on install (NONE exists today — moving the 8.7 MB package off-origin is an offline regression without it). This is genuinely new surface.

**Phase 3 — MIGRATION ENGINE:** `MigrationMap` type; old→new map shipped *with* each release (generated by the build, gated by the Phase-0 test); chained N→N+3 migrations; a persisted `(fromVersion,toVersion)` **idempotency flag in the existing `db.meta` KV** (NOT a regex on segmentId shape — numeric group codes break it); `originalSegmentId` preserved (reversible); **non-blocking fail-safe** (offline / map-404 / evicted-previous-package → degraded banner + retry-on-reconnect, NEVER a gate that locks a user out of their own data).

**Phase 4 — QUARANTINE UX:** `orphanedKm` on `CoverageResult`; a "N rides need review" surface with accept / re-map / keep-as-orphan; schema-v2 cross-lane contract (governance: a steering change to `types.ts` neither lane mutates unilaterally).

**E1 — open ridelog spec:** promote the CSV export into a versioned `ridelog` file (`spec_version` pinned, published JSON Schema); IndexedDB mirrors it; migration history + `originalSegmentId` recorded there.
**E2 — broad-China namespace:** an OSM-ways China build through the Phase-1 pipeline (conflate against 12306; WGS-84, never GCJ-02).
**E3 — open dataset:** schema docs + per-namespace license + a thin reference consumer (`npx ridelog render`).

## What already exists (reuse, don't rebuild)
- `railGeoVersion` pinned on every `RideEvent` — the migration hook is half-wired (`types.ts`, `db.ts`).
- Coverage-warning / orphaned-segment / version-mismatch **detection exists in the store but no `.svelte` reads it** — wiring it is the cheapest high-value win.
- `sid()` in `n02-ingest.ts` already yields `lineId:groupCode` for both endpoints — the new segmentId is a one-commit pipeline change.
- `db.meta` KV table exists (the idempotency-flag home).
- `export.ts` + `import/` = a partial open ridelog (E1 formalizes it).

- GTFS-RT / real-time service data — N02 has none; out of scope.

## Review Corrections (applied from the cross-model review — Codex outside-voice + Claude spec-review, both code-verified)

These tighten the spec; fold each into the named task before building it.

1. **Determinism is a build-time INVARIANT, not a spike observation (T1/T2).** The build dedups stations by arc-distance (`n02-ingest.ts:470-474`), NOT by group code — so a balloon/lollipop/junction-revisit line can place the same group code at two seqs and the `fromGroup-toGroup` pair would collide. The spike proved "0 collisions today," not "0 by construction." Phase 0 MUST assert group-code uniqueness within each line at build time and fail loudly; for the rare legitimate revisit, append an occurrence-index suffix (`lineId:groupA#1-groupB`). Test it.
2. **lineId disambiguator: order-independent anchor (T1).** "Anchor = first station" is positional again (re-anchors on insert). Use **deterministic collision ORDERING**: when slugs collide, sort the colliding lines by a stable anchor `min(stationGroupId)` over each line's group set and suffix by that order (readable, deterministic) — prefer this over hashing; hash only if ordering still ties. Decide the operator-slug freeze (frozen overrides) in the same task.
3. **Migration rewrites event IDENTITY, not just segmentId (T4).** Events are `id = ${tripId}:${segmentId}` (`store.ts:371`). The remap must recompute `id` from the new segmentId consistently per trip, preserve the deterministic-id dedup property, and record `originalSegmentId`. Leaving `id` stale diverges the primary key; changing it naively risks dup/undo breakage.
4. **One-time remap needs NO previous package (T4).** Generate the old(positional)→new(group-pair) table from the CURRENT package alone (it has both the seq list and the group codes for the same segments). No previous-package artifact dependency.
5. **The warning surface is DISTINCT and ADDITIVE (T4).** `dataDegraded` is already wired (`App.svelte:95`, shipped). The unbuilt part is `coverages[].warnings` (kinds `version-mismatch`/`orphaned-segment`, `store.ts:114`/`resolver.ts:223`) — surface it additively, do NOT rebuild the existing strip.
6. **Steering bump is a GATE-0 (T1/T2).** Phase 0 mutates the frozen `types.ts:42` segmentId contract + the "neither lane mutates" header. A steering-control bump co-signed by both lanes must precede T2.
7. **Migration engine edge cases (T7).** (a) event pinned NEWER than the app's target (rollback/stale cache) ⇒ DEGRADED, never remap-down; (b) key idempotency flag + maps by `(namespace, fromVer, toVer)` — JP and CN bump independently (`railGeoVersion` is per-package); (c) `originalSegmentId` = first-ever id, set once, never overwritten across chained N→N+3 hops.
8. **SHA-256 manifest-trust flow (T5).** Manifest integrity FIRST (release-tag pin / SRI / signed manifest) → then per-file `crypto.subtle.digest` over `arrayBuffer()` before `JSON.parse`. Requires HTTPS secure context. A poisoned manifest defeats per-file hashes.
9. **Service-worker ↔ version-pin coupling (T6).** A strict app↔package version pin must precede/accompany the SW (else old-app+new-pkg or new-app+old-cached-pkg skew — the exact failure the plan fears). Sequence the pin with T6, coordinate with T7.
10. **The package is not only JSON (T5).** `public/rail/` has logos + `logo-credits.json`. Decide logos/credits ownership (app-local vs package-owned) or attribution/asset paths break.
11. **Fix the export `lineId` column before E1 (T8).** `export.ts:79` writes a human line NAME in the `lineId` column; formalizing the ridelog schema on top bakes in a misleading column.

## Eng Review lock-down (2026-06-27)

Two engineering decisions made in `/plan-eng-review` (fold into the tasks):
1. **Migration maps are BUILD-generated; the app is apply-only (T4/T7).** The pipeline emits the old(positional)→new(group-pair) map at the scheme-change commit — it alone knows both schemes — and ships it as a migration artifact in the package/manifest. The app NEVER derives IDs; it only applies shipped maps. Kills the dual-derivation drift landmine (an app-side re-derivation that diverges by one edge case would silently rewrite a ride to the wrong segment). The build's ID-derivation is the single source of truth, covered by the golden test.
2. **Upgrade-boot migration is NON-BLOCKING (T4/T7).** On a version-bump boot, render immediately from last-good resolved coverage, run the migration + SHA-256 verify OFF the paint path, then swap in the migrated result with a brief "updated your map" toast. Keeps first paint fast for power users (thousands of events); matches the existing non-blocking degraded-banner posture. Adds a `migrating` status to the state machine.

**Parallelization (worktree lanes):** Phase 0 (T1-T4, pipeline + store + contract) is the sequential foundation — everything depends on it. After it lands: **Lane A** = T5 package/manifest + T6 service-worker (shared infra, sequential within the lane); **Lane B** = T8 E1 ridelog spec (independent of A); **Lane C** = T7 migration engine (depends on T3/T4, independent of A/B). Launch A + B + C in parallel worktrees after Phase 0. Conflict flag: T4 and T7 both touch `store.ts` — sequence them, don't parallelize.
